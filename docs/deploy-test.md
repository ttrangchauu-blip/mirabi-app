# Free test deployment: Render + Neon + Firebase App Distribution

Testers install the Android APK / iOS IPA from Firebase App Distribution (free, works on the Spark plan). The app
talks to the backend on Render's free tier, which stores data in a free Neon PostgreSQL database. No credit card
is needed for any of them; iOS additionally needs a paid Apple Developer account.

```
phone (APK/IPA) ──https──> Render "mirabi-api"  (app.main:app) ──> Neon PostgreSQL
```

## 1. Database (Neon)
SQLite does not work on Render: the container disk is wiped on every restart and deploy.

1. Sign up at https://neon.tech, create a project in region **Asia Pacific (Singapore)**.
2. Copy the connection string (`postgresql://user:pass@ep-....neon.tech/neondb?sslmode=require`). It is used as is;
   [`app/db.py`](../backend/app/db.py) switches it to the psycopg 3 driver.

The backend creates all tables on first start (`app/migrations.py`) and seeds the lessons.

## 2. Backend (Render Blueprint)
[`render.yaml`](../render.yaml) describes the service. It builds the root [`Dockerfile`](../Dockerfile).

1. Sign up at https://render.com with GitHub and give it access to this repository.
2. **New → Blueprint** → pick the repository → Render reads `render.yaml`.
3. Fill in the values it asks for:
   - `DATABASE_URL`: the Neon connection string
   - `ADMIN_EMAILS`: optional, comma-separated accounts that may moderate user reports
4. **Apply**. When the deploy is green, open `https://mirabi-api.onrender.com/health`. It should return
   `{"status":"healthy"}`.

`JWT_SECRET` is generated by Render. Every `git push` to `main` redeploys the service.

Free tier behaviour to expect while testing:
- A service sleeps after 15 minutes without traffic. The next request waits about a minute while it starts.
  Open `/health` in a browser before a test session to wake it.
- Rate limits, realtime rooms and background sweeps live in process memory and reset whenever a service
  restarts (README, *Known limitations*).

## 3. Build the APK / IPA (EAS)
Put the backend URL into [`mobile/eas.json`](../mobile/eas.json) (`build.preview.env.EXPO_PUBLIC_API_URL`,
for example `https://mirabi-api.onrender.com`). The URL is compiled into the app, so changing it needs a new
build. Then, on your computer:

```bash
cd mobile
npx eas-cli@latest login                                   # free Expo account
npx eas-cli@latest build -p android --profile preview      # -> .apk download link
npx eas-cli@latest device:create                           # iOS: register each test iPhone first
npx eas-cli@latest build -p ios --profile preview          # -> ad hoc .ipa, asks for the Apple Developer login
```

Bundle ID / package name: `com.mirabi.app` ([`mobile/app.json`](../mobile/app.json)). Bump `expo.version` for
each test release so testers can tell builds apart.

## 4. Firebase App Distribution
1. Create a Firebase project at https://console.firebase.google.com (Spark plan is enough).
2. Project settings → *Add app*: Android `com.mirabi.app` and iOS `com.mirabi.app`. Skip downloading
   `google-services.json` / `GoogleService-Info.plist`. The app uses only local notifications.
3. Run → **App Distribution** → pick the app → drag in the `.apk` or `.ipa` → add testers' emails (or a tester
   group) → *Distribute*.
4. Testers get an email, accept the invite and install. Android testers must allow installs from unknown
   sources. On iOS the app installs only on devices whose UDID was registered before the build. App Distribution
   can collect UDIDs from invited testers (*Testers & Groups* → export UDIDs → `eas device:create` → rebuild).

Command line alternative:
`npx firebase-tools@latest appdistribution:distribute app.apk --app <FIREBASE_APP_ID> --testers "a@x.com,b@y.com"`.
